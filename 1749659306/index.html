SaltStack

​ 基于 python 开发的一套 C/S 架构配置管理的自动化运维工具，底层使用 ZeroMQ 作为消息队列。和它类似的较为流行的工具 ansible 一样也是基于 python 开发的，两者最大的区别就是 saltstack 是 C/S 架构需要安装客户端，后者 ansible 则无需安装客户端而是使用 ssh 协议

差异 / 项目名 saltstack ansible
开发语言 python python
是否有客户端 是 否
服务器与远程服务器加密方式 AES 通信 openssh 通信
配置文件类型 yaml ini，yaml

​ 在 saltstack 中，server 端是 master，client 端是 minion，两者 通过 zeroMQ 的 pub/sub 发布订阅模式进行通信，可以使用 linux 的包管理工具，或使用 pip 去安装

​ 安装完成后，master 和 minion 文件需要修改一些配置，修改后需要重启服务，master：service salt-master restart，minion：service salt-minion restart

​ 如果 master 没有配置自动认证，那么需要在 master 上执行 salt-key -a <minion id> 来手动通过指定的 minion 连接 master，或者使用 salt-key -A 允许所有的 minion 连接。使用 salt-key 可以查看哪些是通过，拒绝，或是删除的

运行端口

SaltStack master 启动后默认监听 4505 和 4506 两个端口

  • Publisher（4505）：所有 minions 都需要建立一个持续连接到他们收听消息的发布者端口。命令是通过此端口异步发送给所有连接，这使命令可以在大量系统上同时执行
  • Request Server（4506）：minions 根据需要连接到请求服务器，将结果发送给 master，并安全地获取请求的文件或与特定 minion 相关的数据（pillar）

认证过程

  • minion 在第一次启动时，会在 /etc/salt/pki/minion/ 下自动生成一对密钥，然后将公钥发给 master
  • master 收到 minion 的公钥后，通过 salt-key 命令接受该公钥。此时 master 的 /etc/salt/pki/master/minions 目录将会存放以 minion id 命名的公钥，然后 master 就能对 minion 发送控制指令了

其他模块

​ Salt 中还有两个模块 grains 和 pillar

  • Grains 是存储在 minion 的静态元数据信息，如 os，username，num_cpus，mem_total 等
  • Pillar 是存储在 maste 的动态敏感数据，如密码，秘钥，根据需要发送到 minion
    • 使用 pillar，需要在 master 的配置文件中配置和创建这个目录
    •   pillar_roots:
    base:
      - /srv/pillar
  
​    Salt 中还有一个 State 模块，其目的是用于保持 minion 的状态一致，比如 pillar 的信息配置，可以通过 state 来让 minion 去应用，salt 的 state 文件默认 base 是 `/srv/salt` 这个目录下
